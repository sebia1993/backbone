Backbone State Tracker 초급 개발자 가이드

문서 버전: v0.8.32
작성일: 2026-06-12
대상: Python과 Windows 배포를 처음 유지보수하는 개발자

1. 프로젝트 목적

백본 3/4호기의 작업 전후 상태를 읽기 전용 명령으로 수집하고, 스냅샷 간 변경점을 GUI와 HTML/XLSX/JSON 리포트로 확인하는 Windows 운영 도구입니다.

2. 주요 파일

  • core/gui.py: Tkinter GUI, 화면 전환, 수집/비교 버튼 동작
  • core/diff_engine.py: 스냅샷 비교와 등급 분류
  • core/reporter.py: HTML, XLSX, JSON 리포트 생성
  • core/report_bundle.py: 공유 ZIP과 문서 이미지 포함
  • core/workflow.py: 기준 스냅샷과 사용자 지정 단계명 규칙
  • docs/images/: 사용자 가이드용 실제 화면 캡처

3. 개발 환경과 테스트

cd "<folder-that-contains-backbone_state_tracker>\backbone_state_tracker"
python -m pip install -r requirements.txt
$env:PYTHONPATH=(Split-Path (Get-Location) -Parent)
python -m unittest discover -s tests
python app.py --smoke-check

4. 현재 UI 구조

  • 첫 화면과 첫 메뉴는 장비 설정입니다.
  • 좌측 메뉴는 장비 설정, 비교 결과, 작업 로그입니다.
  • 상태 수집은 장비 설정 화면 안에 통합되어 있습니다.
  • 장비 설정 페이지는 세로 스크롤 가능한 Canvas 안에 구성해 장비 행이 늘어도 하단 수집 컨트롤에 접근할 수 있게 합니다.
  • 대상 장비는 기본 2개 입력 행을 만들고, 장비 추가로 필요한 만큼 행을 늘립니다.
  • 장비 YAML을 불러올 때 3대 이상이면 행을 자동 확장하고, 더 짧은 목록을 불러오면 남는 행은 빈 기본값으로 초기화합니다.
  • device_summary_var는 사용 N대 / 입력 N대 / 행 N개 형식으로 대상 장비 입력 상태를 표시합니다.
  • 사용자는 단계명만 입력하며, 비우면 점검시간_YYYYMMDD_HHMM으로 저장됩니다.
  • 수집/비교/샘플 검증 중에는 _track_busy_sensitive()에 등록된 실행 버튼을 비활성화합니다. 실행 흐름에 영향을 주는 버튼을 새로 만들면 같은 목록에 등록합니다.
  • 첫 수집은 기준 스냅샷, 이후 수집은 자동 비교 대상으로 처리됩니다.
  • HTML 리포트는 처음에는 등급 카드만 보이고, 사용자가 긴급/주의/정보/변경없음 중 하나를 선택해야 해당 상태의 바로가기 버튼, 요약 카드, 상세 블록이 표시됩니다. 숨김 상태는 [hidden] CSS와 aria-hidden 동기화로 보강합니다.
  • 샘플 검증 스냅샷은 실제 작업 전 기준 후보에서 제외합니다.
  • GUI 상단 요약과 HTML 리포트 상단 메타에는 샘플 스냅샷을 샘플: 접두어로 표시합니다.

5. 등급 분류 기준

등급기준
Critical장비 접속 실패, 명령 실패, 인터페이스 Down, LACP selected 수 감소, OSPF Full 이탈, cpu_usage 5초/1분/5분 70% 이상, memory_usage FreeRatio 30% 이하, power_status State 비정상, major alarm, fault, abnormal, offline, missing
Warningcpu_usage 5초/1분/5분 50~69%, memory_usage FreeRatio 31~40%, minor alarm, warning, error, 라우팅/STP/로그/리소스 변화
Info접속 복구 또는 일반 출력 변화
Unchanged정규화 후 의미 있는 변화가 없는 항목

6. 릴리스 절차

  1. core/version.py의 APP_VERSION을 올립니다.
  2. CHANGELOG.md와 docs/VERSION_HISTORY.md/html을 갱신합니다.
  3. 사용자/명령어/개발자/체크리스트 문서를 MD와 HTML 모두 갱신합니다.
  4. 전체 테스트와 smoke-check를 실행합니다.
  5. GUI 변경 시 실제 앱 화면을 캡처해 검증합니다.
  6. 소스 ZIP과 Windows EXE ZIP을 빌드하고 Python/PowerShell 검증기를 모두 통과시킵니다.
