Backbone State Tracker 진단/Mock 서버 설계 제안

문서 상태: 구현 전 설계안 | 대상 버전: v0.8.57 | 작성일: 2026-06-15

외부 개발 PC에서 실제 장비 정보 없이 검증하고, 회사 내부망 PC에서는 원본 로그를 외부로 반출하지 않고 오류 코드만으로 원인 분석이 가능하게 만드는 구조입니다.

1. 설계 원칙

  • 실제 장비 로그, 샘플 출력, IP, 호스트명, 계정 정보는 외부 개발 환경으로 가져오지 않습니다.
  • 외부 개발 환경에서는 mock SSH/Telnet 서버와 합성 응답만 사용합니다.
  • 회사 내부망 현장에서는 진단 모드가 단계별 상태와 오류 코드만 남기고 원본 명령 출력은 안전 리포트에서 제외합니다.
  • 외부 전달용 자료는 오류 코드, 단계, 장비 alias, 조치 힌트, 앱 버전, 패키지 해시만 포함합니다.
  • Windows 11 반입 ZIP은 Python 설치 없이 BackboneStateTracker.exe 단독 실행이 가능해야 합니다.

3. 실행 모드

외부 개발 PC mock 검증

BackboneStateTracker.exe --mock-server --profile normal --ssh-port 2222 --telnet-port 2323
BackboneStateTracker.exe --mock-server --profile vrrp_role_change --ssh-port 2222

4. 진단 단계

단계확인 내용원본 로그 저장
startupEXE 버전, 실행 경로, 필수 리소스 존재없음
config명령/장비 설정 형식, 포트 범위없음
security마스킹 정책, 저장 금지 경로, 반출 리포트 범위없음
preflight읽기 전용 명령 여부, 위험 명령 차단없음
networkTCP 연결 가능 여부, SSH/Telnet 배너 단계없음
auth인증 성공/실패 코드화없음
collect명령 실행 성공/실패, 시간 초과원본 출력 제외
report안전 리포트 생성 여부없음
packageEXE ZIP 리소스, manifest, SHA256 확인없음

7. 안전 리포트

outputs/diagnostics/YYYYMMDD_HHMMSS/
  diagnostic_report.html
  diagnostic_report.json
  diagnostic_ticket.txt

허용 항목은 앱 버전, OS, 진단 단계, 오류 코드, 등급, 장비 alias, 안전한 요약, 조치 힌트, 패키지 manifest/SHA256 상태입니다.

금지 항목은 원본 명령 출력, 실제 IP/호스트명/장비명, 계정, 암호, 토큰, SNMP community, 고객명, 위치명, 내부망 도메인, raw snapshot 경로입니다.

8. 구현 단계 제안

  1. v0.8.57-alpha1: 오류 코드, 진단 이벤트, 안전 리포트 기반 구현
  2. v0.8.57-alpha2: mock Telnet 서버와 profile 테스트
  3. v0.8.57-alpha3: mock SSH 서버와 collector 연동 테스트
  4. v0.8.57-beta1: GUI 도움말/진단 실행 통합
  5. v0.8.57: EXE 패키징, 문서, release verifier 마감

9. 구현 전 결정사항

  • mock SSH 서버는 paramiko 기반을 권장합니다.
  • Telnet은 Python telnetlib에 의존하지 않고 socket 기반 서버로 구현하는 것이 안전합니다.
  • 진단 리포트는 원본 로그 포함 옵션을 제공하지 않는 방향을 권장합니다.
  • 장비 alias 원본 매핑 파일은 기본 저장하지 않는 방향을 권장합니다.
  • 기능 규모가 크므로 릴리스는 v0.8.57 계열이 적절합니다.
