# Backbone State Tracker 사용자 가이드

문서 버전: v0.8.1
작성일: 2026-06-11
대상: 백본 3/4호기 상태 점검 및 휴전 작업 검증 담당자

## 1. 핵심 운영 포인트

- 먼저 `작업 전` 상태를 수집합니다. 이후 `백본3 OFF 중`, `복구 후`, `사용자 지정` 단계는 최신 `작업 전` 스냅샷과 자동 비교됩니다.
- 장비 변경 명령은 실행하지 않습니다. `config/commands.yaml`에 정의된 읽기 전용 점검 명령만 실행합니다.
- 수집 전 `설정 점검`으로 장비 목록, 포트, 명령 ID 중복, 변경성 명령 의심 항목을 먼저 확인합니다.
- 암호는 저장하지 않습니다. 프로그램 종료 후 다시 입력해야 합니다.
- 비교 리포트는 HTML, XLSX, JSON으로 생성되며 `outputs/snapshots/` 아래에 저장됩니다.
- 각 비교 결과마다 공유용 ZIP이 함께 생성됩니다. 이 ZIP은 마스킹된 리포트와 사용자 문서를 포함하고, 스냅샷 `raw/` 원본 출력 폴더는 제외합니다.
- GUI 로그, 스냅샷 메타데이터, 비교 리포트는 `password`, `secret`, `token`, `authorization`, `snmp community` 같은 명백한 비밀값을 `***`로 마스킹합니다.
- 명령별 `raw/*.txt` 원본 출력은 운영 증거 보존을 위해 그대로 저장됩니다. 외부 공유 전에는 원본 출력에 민감 정보가 없는지 별도로 확인합니다.
- 긴급 또는 주의 변경점이 나오면 해당 명령의 원본 출력 파일과 HTML 리포트를 함께 확인합니다.
- 비교 결과에서 변경된 라인의 `변경 전`과 `변경 후` 값을 직접 확인합니다.
- GUI 비교 결과는 `판단`, `라인`, `변경 내용`을 한 행에 보여주며, 행 선택 시 핵심 판단과 추적 포인트를 먼저 표시합니다.
- HTML 리포트는 변경 내용을 `기존값 → 신규값` 형태로 한 줄에 표시합니다.
- 장비 1대가 접속 불가이면 해당 장비는 `device_connectivity` 긴급 항목으로 비교 결과에 포함됩니다.
- `샘플 검증 생성`은 실제 장비에 접속하지 않고 `[샘플]` 스냅샷과 비교 리포트를 만들어 기능 확인에 사용합니다.
- 같은 단계의 스냅샷을 같은 초에 다시 수집해도 기존 폴더를 덮지 않고 `_001` 같은 별도 폴더로 저장합니다.
- 대시보드의 `작업 진행 마법사`를 따라가면 다음 단계 버튼으로 작업 흐름을 이어갈 수 있습니다.

## 2. 프로그램 동작 방식

1. `대시보드`의 작업 진행 마법사에서 현재 단계와 다음 액션을 확인합니다.
2. 필요 시 `장비 설정` 화면에서 백본 3/4호기 IP, 포트, 장비 타입, 접속 계정을 입력합니다.
3. 프로그램이 장비에 SSH로 접속해 읽기 전용 명령을 실행합니다.
4. 장비별 접속 상태와 명령 출력이 시간별 스냅샷 폴더에 저장됩니다.
   같은 초에 동일 단계가 다시 저장되면 폴더명 뒤에 `_001`, `_002` 순번이 붙습니다.
5. 작업 전이 아닌 단계는 최신 `작업 전` 스냅샷과 자동 비교됩니다.
6. `비교 결과` 화면 또는 `최근 리포트` 버튼으로 변경점을 확인합니다.

## 3. 샘플 검증 모드

- `대시보드` 또는 `비교 결과` 화면의 `샘플 검증 생성` 버튼을 누르면 예제 스냅샷 3개가 생성됩니다.
- 생성되는 스냅샷은 `[샘플] 작업 전`, `[샘플] 백본3 OFF 중`, `[샘플] 복구 후`입니다.
- 이 기능은 SSH 접속, 계정 입력, 실제 장비 명령 실행을 하지 않습니다.
- 백본3 접속 불가, 백본4 측 링크 DOWN, 복구 후 접속 회복 예시를 비교 리포트로 확인할 수 있습니다.
- 샘플 결과는 `outputs/snapshots/` 아래에 저장되므로 실제 작업 리포트와 구분해 보관합니다.

## 4. 화면 구성

### 대시보드

- 긴급, 주의, 정보, 변경없음 건수를 요약합니다.
- 최근 스냅샷, 최근 리포트, 현재 비교 상태를 보여줍니다.
- `작업 진행 마법사`가 장비 설정 확인, 작업 전 수집, 백본3 OFF 중 수집, OFF 중 변경 확인, 복구 후 수집, 최종 확인 순서로 안내합니다.
- `다음 단계` 버튼은 완료 결과를 확인한 뒤에만 다음 작업으로 넘어가도록 설계되어 있습니다.

### 상태 수집

- `작업 전`, `백본3 OFF 중`, `복구 후`, `사용자 지정` 단계 중 하나를 선택합니다.
- 사용자 지정 단계는 별도 단계명이 필요할 때 사용합니다.
- `설정 점검` 버튼은 실제 장비 접속 없이 로컬 설정을 확인합니다. 오류가 있으면 수집이 차단되고, 주의만 있으면 운영자가 확인 후 수집할 수 있습니다.
- 예시용 IP, 장비명/IP 중복, 위험해 보이는 명령, `check` 단계 명령 누락을 먼저 확인합니다.

### 비교 결과

- 기준 스냅샷과 비교 스냅샷을 직접 선택해 다시 비교할 수 있습니다.
- 자동 비교가 누락되었거나 특정 시점끼리 재확인이 필요할 때 사용합니다.
- `최근 변경 상세` 목록은 등급, 장비, 명령, 판단, 유형, 라인, 변경 내용을 표시합니다.
- `등급` 필터와 `검색` 입력으로 긴급/주의 항목, 특정 장비, 명령, 인터페이스, 변경값만 좁혀 볼 수 있습니다.
- 검색은 표시되는 마스킹 값 기준으로 동작하므로 비밀값 원문은 검색 결과에 노출되지 않습니다.
- 변경 행을 선택하면 핵심 판단, 변경 전/후 값, 원본 파일 위치, 등급별 운영 메모를 확인할 수 있습니다.
- 접속 불가 장비는 일반 명령 누락을 여러 건으로 나열하지 않고 `device_connectivity` 긴급 항목 한 줄로 표시합니다.

### 장비 설정

- 백본 3/4호기 접속 정보와 SSH 계정을 입력합니다.
- `장비 목록 저장`은 장비 정보만 저장합니다. 암호는 저장하지 않습니다.

### 작업 로그

- 수집 시작, 저장 위치, 비교 완료, 오류 메시지를 확인합니다.

## 5. 권장 작업 순서

1. `장비 설정`에서 백본 3/4호기 정보와 접속 계정을 확인합니다.
2. `상태 수집` 화면에서 `설정 점검`을 실행해 차단 오류가 없는지 확인합니다.
3. 대시보드의 `작업 전 수집 시작` 버튼으로 기준 스냅샷을 생성합니다.
4. 백본 3호기 OFF, 백본 4호기 ON 상태에서 `백본3 OFF 중 수집 시작`을 실행합니다.
5. `OFF 중 변경 상세 확인`으로 자동 비교 결과의 긴급/주의 항목을 확인합니다.
6. 복구 후 백본 3/4호기 ON 상태에서 `복구 후 수집 시작`을 실행합니다.
7. `최종 변경 상세 확인`과 `최종 리포트 열기`로 작업 결과를 보관합니다.

## 6. 리포트 확인

- `최근 리포트`: 현재 실행 세션에서 마지막으로 생성된 HTML 리포트를 엽니다.
- `공유 ZIP`: 현재 실행 세션에서 마지막으로 생성된 공유용 ZIP을 엽니다. 사내 반입이나 메일 첨부에는 이 파일을 우선 사용합니다.
- `결과 폴더`: 전체 스냅샷과 리포트가 저장된 폴더를 엽니다.
- XLSX 리포트는 변경점 공유나 회의 자료 정리에 사용합니다.
- HTML 리포트는 명령별 변경 상세 테이블과 원본 unified diff를 함께 제공합니다.
- HTML, XLSX, JSON manifest에는 명백한 비밀값이 `***`로 표시됩니다. 장비명, IP, 인터페이스, VLAN, 라우팅 값처럼 비교 추적에 필요한 운영 식별자는 자동 마스킹하지 않습니다.
- 공유 ZIP에는 `reports/` 아래의 리포트 파일과 `docs/` 아래의 사용자 문서가 들어갑니다. `raw/`, `config/devices.yaml`, 실행파일은 포함하지 않습니다.
- HTML 변경 상세는 `유형`, `라인`, `변경 내용` 구조입니다. 변경 행은 `기존값 → 신규값`, 추가 행은 `추가: 신규값`, 삭제 행은 `삭제: 기존값`으로 표시됩니다.
- 장비 접속 실패는 `reachable → unreachable: timeout`처럼 접속 상태 변경으로 표시됩니다.
- 명령 출력이 긴 경우 HTML 리포트의 변경 상세 영역에서 가로 스크롤로 확인합니다.
- GUI의 `라인` 값은 `기준 라인 → 비교 라인` 형태입니다. 예를 들어 `2 → 2`는 같은 행의 값이 바뀐 경우이고, `- → 4`는 비교 스냅샷에 추가된 행입니다.
- GUI 비교 상세의 `초기화` 버튼은 등급 필터와 검색어를 모두 지우고 전체 변경 행을 다시 표시합니다.
- XLSX 리포트의 `diff_detail` 시트는 장비, 명령, 변경 유형, 기준 라인, 비교 라인, 변경 전/후 값을 행 단위로 제공합니다.

## 7. 주의 사항

- 운영 장비 대상이므로 작업 전 승인된 점검 시간과 접속 권한을 확인합니다.
- 샘플 스냅샷은 교육/검증용입니다. 실제 휴전 결과로 제출할 때는 `[샘플]` 표기가 없는 실제 수집 리포트를 사용합니다.
- 리포트와 로그의 마스킹은 보조 안전장치입니다. 장비 출력 원본을 그대로 전달해야 하는 경우를 제외하고, 대외 제출 전에는 HTML/XLSX 리포트 중심으로 공유합니다.
- 사내 반입용 ZIP에는 로컬 `config/devices.yaml`과 `outputs/`가 포함되지 않도록 유지합니다.
- 실제 장비 설정 변경, 재부팅, 포트 shutdown 같은 명령은 이 도구에 추가하지 않습니다.

## 8. 배포 ZIP 무결성 확인

- v0.8.0부터 `dist/`에 ZIP 파일과 같은 이름의 `.sha256.txt` 파일이 함께 생성됩니다.
- `dist/backbone_state_tracker_v0.8.1_YYYYMMDD_release_manifest.txt`에는 같은 버전의 소스 ZIP과 Windows EXE ZIP 이름, 크기, SHA256 값이 정리됩니다.
- ZIP 내부의 `PACKAGE_INFO.txt`에서 패키지 종류, 포함 파일, 제외 항목, 검증 방법을 다시 확인할 수 있습니다.
- 사내 반입 후 PowerShell에서 아래 명령을 실행하고, 결과 해시가 `.sha256.txt` 또는 `release_manifest.txt`의 SHA256 값과 같은지 비교합니다.
- v0.8.1부터는 소스/배포 작업 폴더가 있는 경우 `tools/verify_release_package.py`로 ZIP 내부 필수 파일과 금지 파일 포함 여부까지 함께 점검할 수 있습니다.

```powershell
Get-FileHash -Algorithm SHA256 .\backbone_state_tracker_v0.8.1_YYYYMMDD_windows_exe.zip
# 아래 명령은 소스/배포 작업 폴더에서 실행합니다.
python .\tools\verify_release_package.py .\dist\backbone_state_tracker_v0.8.1_YYYYMMDD_windows_exe.zip --require-manifest
```
