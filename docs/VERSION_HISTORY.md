## 2. v0.8.4 변경내역

### 추가 및 변경

- `docs/COMMAND_GUIDE.md`와 `docs/COMMAND_GUIDE.html`을 추가했습니다.
- `config/commands.yaml`에 포함된 HPE/Comware 읽기 전용 점검 명령의 의미, 정상 기준, 추적 포인트를 한글 표로 정리했습니다.
- 사용자 가이드와 개발자 가이드에서 명령어 가이드를 참조하도록 업데이트했습니다.
- Python/PowerShell 배포 ZIP 검증 기준에 명령어 가이드 MD/HTML을 필수 문서로 추가했습니다.

### 운영 영향

- 운영자는 백본 3/4호기에서 수집되는 각 명령이 무엇을 확인하는지 ZIP 내부 문서만으로 확인할 수 있습니다.
- 장비 수집 명령 자체와 비교 엔진 동작은 변경하지 않았습니다.

## 3. v0.8.3 변경내역

### 추가 및 변경

- 수집, 수동 비교, 샘플 검증 생성이 진행 중일 때 같은 작업을 다시 시작하지 못하도록 GUI 진입점에 busy guard를 추가했습니다.
- 작업 진행 중에는 수집/비교/샘플 생성 버튼을 비활성화하여 중복 SSH 세션이나 중복 리포트 생성을 줄였습니다.
- `tools/build_release.ps1`와 `tools/build_windows_exe.ps1`가 빌드 후 `dist/latest/`와 `dist/CURRENT_RELEASE.txt`를 갱신하도록 보강했습니다.
- busy guard 회귀 테스트를 `tests/test_gui_formatting.py`에 추가했습니다.

### 운영 영향

- 운영자가 수집 또는 비교 버튼을 실수로 반복 클릭해도 진행 중인 작업이 끝나기 전에는 새 작업이 시작되지 않습니다.
- `dist/`에 여러 과거 버전 ZIP이 남아 있어도 `dist/latest/` 또는 `CURRENT_RELEASE.txt`를 기준으로 최신 반입 대상 파일을 확인할 수 있습니다.
- 장비 수집 명령, 스냅샷 형식, 리포트 형식은 변경하지 않았습니다.

## 4. v0.8.2 변경내역

### 추가 및 변경

- `tools/verify_release_package.ps1`를 추가하여 PowerShell만으로 ZIP 해시, sidecar, release manifest, 필수 파일, 금지 경로를 검증할 수 있게 했습니다.
- 소스/EXE 빌드 스크립트가 `dist/backbone_state_tracker_v<버전>_<날짜>_verify_release_package.ps1`를 함께 생성하도록 보강했습니다.
- 소스 ZIP 필수 파일 검증 기준에 PowerShell 검증 스크립트를 추가했습니다.
- 사용자/개발자 가이드에 Python 검증과 독립 PowerShell 검증 절차를 모두 문서화했습니다.

### 운영 영향

- 사내 반입 시 소스 폴더나 Python 환경이 없어도 ZIP, `.sha256.txt`, `release_manifest.txt`, `*_verify_release_package.ps1`만 있으면 배포물 검증이 가능합니다.
- 기존 수집, 비교, 리포트 생성 동작은 변경하지 않았습니다.

## 5. v0.8.1 변경내역

### 추가 및 변경

- `tools/verify_release_package.py`를 추가하여 배포 ZIP의 sidecar SHA256, 파일 크기, release manifest 기록을 검증합니다.
- 소스 ZIP과 Windows EXE ZIP의 필수 파일 목록을 확인하고, `.git`, `outputs/`, `dist/`, `build/`, `raw/`, `config/devices.yaml`, 캐시 파일 같은 금지 경로가 들어가면 오류로 처리합니다.
- `tools/build_release.ps1`와 `tools/build_windows_exe.ps1`가 ZIP 생성 직후 검증 도구를 자동 실행하도록 보강했습니다.
- 정상 소스 ZIP, 해시/크기 불일치, 로컬 `config/devices.yaml` 포함 차단에 대한 단위 테스트를 추가했습니다.
- 사용자/개발자 가이드에 반입 후 검증 명령을 추가했습니다.

### 운영 영향

- 사내 반입 후 ZIP이 변조되지 않았는지뿐 아니라, 실행/문서 필수 파일이 누락되지 않았는지와 민감한 로컬 설정이 섞이지 않았는지도 한 번에 확인할 수 있습니다.
- 기존 수집, 비교, 리포트 생성 동작은 변경하지 않았습니다.

## 6. v0.8.0 변경내역

### 추가 및 변경

- 소스 ZIP과 Windows EXE ZIP 생성 후 같은 이름의 `.sha256.txt` 파일을 자동 생성합니다.
- 같은 버전의 배포 ZIP 이름, 파일 크기, SHA256 값을 정리한 `release_manifest.txt`를 `dist/`에 생성합니다.
- 각 ZIP 내부에 `PACKAGE_INFO.txt`를 포함하여 패키지 종류, 포함 파일, 제외 항목, 검증 방법을 확인할 수 있게 했습니다.
- Windows EXE ZIP staging에서 로컬 `config/devices.yaml`이 발견되면 제거하도록 보강했습니다.
- 릴리스 매니페스트 생성 로직을 `tools/write_release_manifest.py`로 분리하고 단위 테스트를 추가했습니다.
- 소스/EXE 배포 스크립트와 사용자/개발자 가이드를 무결성 확인 절차에 맞게 업데이트했습니다.

### 운영 영향

- 사내 반입 후 `Get-FileHash -Algorithm SHA256` 결과를 `.sha256.txt` 또는 `release_manifest.txt`와 비교해 ZIP 변조/전송 오류 여부를 확인할 수 있습니다.
- 기존 수집, 비교, 리포트 생성 동작은 변경하지 않았습니다.

## 7. v0.7.9 변경내역

### 추가 및 변경

- `상태 수집` 화면에 `설정 점검` 버튼과 점검 상태 요약을 추가했습니다.
- 장비명 중복, 빈 호스트, 잘못된 포트, 예시용 IP, 중복 명령 ID, `check` 단계 명령 누락을 로컬에서 확인합니다.

- 수집 전 검증 단위 테스트를 추가했습니다.

### 운영 영향

- 설정 실수나 위험 명령이 작업 중에 발견되는 상황을 줄일 수 있습니다.
- 실제 장비 접속 없이 로컬 파일과 입력값만 확인하므로 사전 점검에 사용할 수 있습니다.

## 8. v0.7.8 변경내역

### 추가 및 변경

- GUI `최근 변경 상세` 목록에 등급 필터와 검색 입력을 추가했습니다.

- 검색은 마스킹된 표시값 기준으로 수행되어 비밀값 원문을 검색 결과에 노출하지 않습니다.

- 변경 행이 많은 비교 결과에서 긴급/주의 항목이나 특정 인터페이스만 빠르게 좁혀 볼 수 있습니다.
- HTML/XLSX/JSON 리포트 형식과 raw 스냅샷 보존 방식은 변경하지 않았습니다.

## 9. v0.7.7 변경내역

### 추가 및 변경

- 각 스냅샷 비교 결과마다 공유용 리포트 ZIP을 자동 생성합니다.
- 공유 ZIP에는 마스킹된 HTML/XLSX/CSV/JSON 리포트와 사용자 가이드/명령어 가이드/버전 변경내역 문서를 포함합니다.
- 공유 ZIP에서 스냅샷 `raw/` 원본 출력, 로컬 `config/devices.yaml`, 실행파일은 제외합니다.
- 대시보드와 비교 화면에 `공유 ZIP` 버튼을 추가했습니다.
- 샘플 검증 비교도 공유 ZIP을 생성하도록 확장했습니다.

### 운영 영향

- 메일 첨부나 사내 반입 시 raw 원본 출력이 포함된 전체 결과 폴더 대신 공유용 ZIP을 사용할 수 있습니다.
- 리포트 내 명백한 비밀값은 v0.7.6 기준으로 계속 `***` 처리됩니다.
- 토폴로지 식별 정보가 민감한 환경에서는 공유 ZIP도 제출 전 검토해야 합니다.

## 10. v0.7.6 변경내역

### 추가 및 변경

- GUI 작업 로그, 스냅샷 메타데이터, HTML/XLSX/JSON 비교 리포트에 민감 문자열 마스킹을 적용했습니다.
- `password`, `secret`, `token`, `authorization`, URL credential, Cisco typed secret, SNMP community 문자열을 `***`로 표시합니다.
- 명령별 `raw/*.txt` 원본 출력 파일은 운영 증거 보존을 위해 그대로 유지합니다.
- 연결 실패 오류와 명령 실패 예외 메시지도 같은 마스킹 규칙을 사용합니다.
- `tests/test_redaction.py`와 리포트 마스킹 회귀 테스트를 추가했습니다.

### 운영 영향

- 외부 공유용 HTML/XLSX/JSON 리포트에서 명백한 비밀값 노출 가능성이 줄었습니다.
- 장비명, IP, 인터페이스, VLAN, 라우팅 값처럼 변경 추적에 필요한 운영 식별자는 자동 마스킹하지 않습니다.
- 원본 명령 출력 파일은 그대로 남으므로 대외 제출 전에는 raw 파일 공유 범위를 별도로 확인해야 합니다.

## 13. v0.7.3 변경내역

## 26. 반입 전 확인사항

- ZIP 파일명에 의도한 버전이 포함되어 있는지 확인합니다.
- `dist/latest/` 또는 `dist/CURRENT_RELEASE.txt`가 현재 반입할 버전을 가리키는지 확인합니다.
- ZIP 내부에 `PACKAGE_INFO.txt`가 있는지 확인합니다.
- ZIP과 같은 이름의 `.sha256.txt` 파일이 `dist/`에 있는지 확인합니다.
- 반입 후 `Get-FileHash -Algorithm SHA256` 결과가 `.sha256.txt` 또는 `release_manifest.txt`와 같은지 확인합니다.
- `python .\tools\verify_release_package.py .\dist\<package>.zip --require-manifest` 검증이 성공하는지 확인합니다.
- 소스 폴더가 없는 환경에서는 `powershell -ExecutionPolicy Bypass -File .\<version>_verify_release_package.ps1 -Package .\<package>.zip -RequireManifest` 검증이 성공하는지 확인합니다.
- `docs/` 폴더에 사용자 가이드, 명령어 가이드, 개발자 가이드, 버전 변경내역 문서가 Markdown/HTML 모두 있는지 확인합니다.
- 소스 ZIP에 `.git`, `outputs/`, `dist/`, `config/devices.yaml`이 포함되지 않았는지 확인합니다.
- Windows EXE ZIP에 `BackboneStateTracker.exe`가 포함되어 있는지 확인합니다.
- 장비 IP, 계정, 원본 출력 등 내부 정보가 배포 파일에 포함되지 않았는지 확인합니다.
